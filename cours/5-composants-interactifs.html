Ouvrir la modale : trois lignes utiles

const dialog = document.querySelector("#ticket-dialog");
const opener = document.querySelector("#open-ticket");
const message = document.querySelector("#message");

opener.addEventListener("click", () => {
  dialog.returnValue = "";
  dialog.showModal(); // modale : le reste de la page devient inerte
});

// Le bouton qui envoie le formulaire donne sa value à returnValue
dialog.addEventListener("close", () => {
  if (dialog.returnValue !== "confirm") return;
  const quantity = dialog.querySelector("#quantity").value;
  message.textContent = `${quantity} pass ajouté(s) au panier.`;
});

// Clic sur le fond : la cible est l'élément dialog lui-même,
// car le formulaire occupe tout l'intérieur de la modale
dialog.addEventListener("click", (event) => {
  if (event.target === dialog) dialog.close("cancel");
});

Ce que showModal() fait pour vous

  • Affiche la modale dans la top layer, au-dessus de tout, sans z-index
  • Rend le reste de la page inerte : ni clic ni tabulation derrière
  • Place le focus dans la modale. Échap la ferme et le focus revient au bouton
  • returnValue dit quel bouton l'a fermée
  • L'attribut closedby="any" ferme au clic sur le fond. Pas encore dans Safari : le dernier écouteur sert de repli

Animer l'ouverture… et la fermeture

/* État fermé : l'élément dialog est en display: none */
dialog {
  opacity: 0;
  translate: 0 1rem;
  transition:
    opacity 0.25s,
    translate 0.25s,
    overlay 0.25s allow-discrete,
    display 0.25s allow-discrete;
}

dialog[open] {
  opacity: 1;
  translate: 0 0;
}

/* Point de départ de l'animation, à l'ouverture */
@starting-style {
  dialog[open] {
    opacity: 0;
    translate: 0 1rem;
  }
}

/* Le fond assombri, propre aux modales */
dialog::backdrop {
  background-color: rgb(20 18 40 / 0%);
  transition:
    background-color 0.25s,
    overlay 0.25s allow-discrete,
    display 0.25s allow-discrete;
}

dialog[open]::backdrop {
  background-color: rgb(20 18 40 / 60%);
}

@starting-style {
  dialog[open]::backdrop {
    background-color: rgb(20 18 40 / 0%);
  }
}

@media (prefers-reduced-motion: reduce) {
  dialog,
  dialog::backdrop {
    transition: none;
  }
}
  • Une modale fermée est en display: none. Jusqu'ici, impossible de l'animer
  • allow-discrete retarde le passage à display: none jusqu'à la fin de la transition. overlay garde la modale dans la top layer pendant ce temps
  • @starting-style décrit l'état de départ, juste à l'ouverture
  • prefers-reduced-motion : on coupe l'animation pour les personnes que le mouvement gêne

Une infobulle avec la Popover API

<!doctype html>
<html lang="fr">
  <head>
    <meta charset="utf-8" />
    <meta
      name="viewport"
      content="width=device-width, initial-scale=1"
    />
    <title>Les pass – Contrepoint</title>
    <link rel="stylesheet" href="css/base.css" />
    <link rel="stylesheet" href="css/style.css" />
  </head>
  <body>
    <main>
      <h1>Les pass</h1>
      <p>
        Le <strong>pass nuit</strong> ouvre les concerts après 23 h.
        <button
          type="button"
          class="hint-trigger"
          popovertarget="night-hint"
          aria-label="En savoir plus sur le pass nuit"
        >
          ?
        </button>
      </p>
      <!-- popover (auto) : Échap ou un clic ailleurs le ferme -->
      <div id="night-hint" class="hint" popover>
        Valable du vendredi au dimanche, de 23 h à 4 h. Navettes
        gratuites vers la gare.
      </div>
    </main>
  </body>
</html>
  • popover : l'élément est caché puis affiché dans la top layer
  • popovertarget relie le bouton à son popover. Le clic l'ouvre et le referme, sans JavaScript
  • Le navigateur gère aria-expanded sur le bouton, Échap et le clic à l'extérieur (light dismiss)
  • popover="manual" : seule une action explicite le ferme (une notification, par exemple)

  border-radius: var(--radius);
  color: white;

@supports (anchor-name: --a) {

  • anchor-name nomme l'ancre. position-anchor s'y accroche

  • inset: auto annule le centrage par défaut des popovers
  • Chrome et Edge 125, Safari 26. Pas encore Baseline : @supports garde un popover centré ailleurs

View Transitions : animer un changement

const stage = document.querySelector(".stage img");
const caption = document.querySelector(".stage figcaption");
const thumbs = document.querySelector(".thumbs");

async function show(button) {
  const thumb = button.querySelector("img");
  stage.src = `https://picsum.photos/id/${button.dataset.id}/960/540`;
  stage.alt = thumb.alt;
  caption.textContent = button.dataset.caption;
  thumbs
    .querySelector("[aria-current]")
    .removeAttribute("aria-current");
  button.setAttribute("aria-current", "true");
  // Attendre l'image : la capture « après » la montre chargée
  await stage.decode().catch(() => {});
}

// Délégation : un seul écouteur pour toutes les miniatures
thumbs.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button) return;
  // Repli : sans l'API, on change l'image sans animation
  if (!document.startViewTransition) {
    show(button);
    return;
  }
  document.startViewTransition(() => show(button));
});
  • startViewTransition() photographie la page, applique la modification puis anime de l'ancien état vers le nouveau
  • La fonction peut être async : ici on attend que la nouvelle image soit décodée
  • Amélioration progressive : sans l'API, la galerie fonctionne sans animation
  • aria-current signale la miniature active, au lecteur d'écran comme au CSS

JavaScript natif

Quand le HTML ne suffit plus

Hier : jQuery

// jQuery (2006) : sélectionner, écouter, modifier en une ligne
// À ne plus reproduire : rien ne dit au lecteur d'écran que le
// menu est ouvert (pas d'aria-expanded)
$(function () {
  $(".menu-toggle").on("click", function () {
    $(".menu").toggleClass("is-open");
  });
});
  • jQuery (2006) a gommé les différences entre navigateurs et rendu le DOM agréable : $(".menu"), .on(), .toggleClass()
  • Ses idées sont devenues des standards : querySelector, classList, addEventListener, fetch
  • Aujourd'hui, c'est 30 Ko à télécharger pour ce que le navigateur fait déjà. Vous le croiserez encore dans des sites existants
Ce code ne dit pas au lecteur d'écran que le menu est ouvert.
Ouvrir la démo

Aujourd'hui : le même menu en JS natif

// JS natif : un seul écouteur sur le document (délégation),
// valable pour tous les boutons qui pilotent un autre élément
document.addEventListener("click", (event) => {
  const button = event.target.closest("button[aria-controls]");
  if (!button) return;
  const id = button.getAttribute("aria-controls");
  const target = document.getElementById(id);
  const expanded = button.getAttribute("aria-expanded") === "true";
  // L'état est lu dans le HTML et annoncé au lecteur d'écran
  button.setAttribute("aria-expanded", String(!expanded));
  target.hidden = expanded;
});
  • Délégation d'événements : un seul écouteur sur le document. closest() retrouve le bouton cliqué, même ajouté plus tard
  • aria-expanded porte l'état. Il est lu par le lecteur d'écran et sert de sélecteur au CSS
  • aria-controls désigne l'élément piloté : le même script sert à tous les boutons de ce type
  • L'attribut hidden cache le menu, pour tout le monde

Des onglets accessibles : le clavier

// Motif « Tabs » de l'APG du W3C : un seul onglet dans l'ordre
// de tabulation, les flèches passent d'un onglet à l'autre
const tablist = document.querySelector('[role="tablist"]');
const tabs = [...tablist.querySelectorAll('[role="tab"]')];

function select(tab) {
  for (const other of tabs) {
    const selected = other === tab;
    other.setAttribute("aria-selected", String(selected));
    other.tabIndex = selected ? 0 : -1;
    const panelId = other.getAttribute("aria-controls");
    document.getElementById(panelId).hidden = !selected;
  }
  tab.focus();
}

tablist.addEventListener("click", (event) => {
  const tab = event.target.closest('[role="tab"]');
  if (tab) select(tab);
});

tablist.addEventListener("keydown", (event) => {
  const index = tabs.indexOf(document.activeElement);
  const targets = {
    ArrowRight: index + 1,
    ArrowLeft: index - 1,
    Home: 0,
    End: tabs.length - 1,
  };
  if (!(event.key in targets)) return;
  event.preventDefault();
  // at() accepte -1 (dernier) ; le modulo revient au premier
  select(tabs.at(targets[event.key] % tabs.length));
});
  • Tab entre dans la liste puis passe au panneau. Les flèches changent d'onglet, Début et Fin vont aux extrémités
  • Technique du roving tabindex : l'onglet actif a tabIndex = 0, les autres -1
  • tab.focus() : le focus suit la sélection. Ne jamais le perdre
  • Testez-le au clavier puis avec VoiceOver ou NVDA

Web Components

Vos propres éléments HTML, sans framework

Quatre standards du navigateur

Custom elements

customElements.define() crée une balise comme <cp-countdown>. Son nom contient toujours un tiret

Shadow DOM

Un DOM privé : son CSS ne fuit pas vers la page et le CSS de la page n'y entre pas

Template et slots

<template> : du HTML cloné à chaque instance. <slot> : là où s'affiche le contenu fourni par la page

Thème

Deux portes vers l'intérieur : ::part() et les custom properties, qui traversent le Shadow DOM
Un Web Component fonctionne dans n'importe quelle page, avec ou sans React, Vue ou Angular. Baseline depuis 2020.

Le composant <cp-countdown>

const template = document.createElement("template");
template.innerHTML = `
  <style>
    :host { display: inline-block; }
    .box {
      display: flex;
      gap: var(--cp-gap, 1rem);
      padding: 1rem 1.5rem;
      border-radius: var(--cp-radius, 12px);
      color: var(--cp-on-surface, white);
      background: var(--cp-surface, #1b1e3c);
    }
    .unit { display: grid; text-align: center; }
    .value {
      font-size: 2rem;
      font-weight: 700;
      font-variant-numeric: tabular-nums;
    }
  </style>
  <p part="label"><slot>Début du festival dans</slot></p>
  <div class="box" part="box" role="timer">
    <span class="unit"><span class="value" id="days"></span>jours</span>
    <span class="unit"><span class="value" id="hours"></span>h</span>
    <span class="unit"><span class="value" id="minutes"></span>min</span>
    <span class="unit"><span class="value" id="seconds"></span>s</span>
  </div>
`;

class CpCountdown extends HTMLElement {
  static observedAttributes = ["date"];
  #timer;

  constructor() {
    super();
    const root = this.attachShadow({ mode: "open" });
    root.append(template.content.cloneNode(true));
  }

  connectedCallback() {
    this.#render();
    this.#timer = setInterval(() => this.#render(), 1000);
  }

  disconnectedCallback() {
    clearInterval(this.#timer);
  }

  attributeChangedCallback() {
    this.#render();
  }

  #render() {
    const end = new Date(this.getAttribute("date")).getTime();
    const rest = Math.max(0, (end - Date.now()) / 1000) || 0;
    const values = {
      days: rest / 86400,
      hours: (rest % 86400) / 3600,
      minutes: (rest % 3600) / 60,
      seconds: rest % 60,
    };
    for (const [id, value] of Object.entries(values)) {
      const cell = this.shadowRoot.getElementById(id);
      cell.textContent = String(Math.floor(value)).padStart(2, "0");
    }
  }
}

customElements.define("cp-countdown", CpCountdown);
  • attachShadow() crée le Shadow DOM, rempli par un clone du template
  • :host : l'élément lui-même vu de l'intérieur. var(--cp-surface, #1b1e3c) : un réglage avec sa valeur par défaut
  • Cycle de vie : connectedCallback à l'insertion dans la page, disconnectedCallback au retrait (on arrête le minuteur), attributeChangedCallback quand un attribut de observedAttributes change
  • part="label" expose un élément au CSS de la page

Shadow DOM ou Light DOM pour un framework CSS ?

Shadow DOM : un composant fermé

  • Style isolé, impossible à casser par la page
  • Idéal pour un widget autonome (lecteur audio, compte à rebours)
  • Dans un formulaire, il faut ElementInternals : static formAssociated = true, puis attachInternals(), setFormValue() et setValidity() pour que la valeur soit envoyée et validée Baseline 2023

Light DOM : un composant qui enrichit du HTML

  • Sans attachShadow() : le JS ajoute le comportement, vos classes CSS s'appliquent
  • Le HTML reste lisible sans JS (amélioration progressive), indexable et stylable par vos tokens
  • Pour votre framework, c'est souvent le bon choix : <cp-tabs> qui entoure des onglets en HTML ordinaire

Performance

Un beau CSS ne sert à rien sur une page qui saute

Les Core Web Vitals

LCP ≤ 2,5 s

Largest Contentful Paint : temps d'affichage du plus grand élément visible, souvent l'image d'en-tête

CLS ≤ 0,1

Cumulative Layout Shift : les sauts de mise en page. Causes : images sans dimensions, polices qui changent de taille, contenu injecté

INP ≤ 200 ms

Interaction to Next Paint : délai entre un clic et l'affichage qui suit. Ennemi : le JavaScript long
Ces trois mesures, relevées chez de vrais visiteurs, comptent dans le référencement de Google. Le seuil doit être tenu pour 75 % des visites.

Des images et une police qui ne font pas sauter la page

  • width et height sur chaque image : la place est réservée (CLS)
  • srcset et sizes : le navigateur choisit le fichier adapté à l'écran. <picture> propose un format moderne (WebP, AVIF) avec repli
  • fetchpriority="high" sur l'image LCP, loading="lazy" sur les images plus bas
  • preload demande la police avant même de lire le CSS

Polices et rendu différé en CSS

/* La police web ; swap : le texte s'affiche tout de suite */
@font-face {
  font-family: Outfit;
  src: url("../../../../assets/fonts/outfit-latin.woff2")
    format("woff2");
  font-weight: 100 900;
  font-display: swap;
}

/* Police de repli ajustée à Outfit : pas de saut au swap (CLS) */
@font-face {
  font-family: "Outfit fallback";
  src: local("Arial");
  size-adjust: 102%;
  ascent-override: 98%;
  descent-override: 26%;
}

body {
  max-inline-size: 60rem;
  margin: 0 auto;
  font-family: Outfit, "Outfit fallback", sans-serif;
}

/* width et height du HTML donnent le ratio : la place est
   réservée avant le chargement de l'image */
img {
  display: block;
  max-inline-size: 100%;
  block-size: auto;
}

.hero h1 {
  margin: 1rem;
  font-size: clamp(2rem, 6vw, 4rem);
}

main {
  padding: 1rem;
}

.lineup {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(12rem, 1fr));
  gap: 1rem;
  padding: 0;
  list-style: none;
}

/* Hors de l'écran : rendu différé, place estimée à 30rem */
.archives {
  content-visibility: auto;
  contain-intrinsic-size: auto 30rem;
}
  • font-display: swap : le texte s'affiche tout de suite dans la police de repli
  • size-adjust et les *-override calent Arial sur les dimensions d'Outfit : le texte ne bouge plus quand la vraie police arrive. Valeurs calculées avec un outil comme Fontaine
  • content-visibility: auto : une section hors de l'écran n'est mise en page qu'à l'approche Baseline 2024

Mesurer, puis alléger

Mesurer

  • Lighthouse (DevTools) : un score et une liste de corrections, en navigation privée, en simulant un mobile
  • Panneau Performance : les Core Web Vitals en direct. L'élément LCP et les décalages y sont surlignés
  • En CI, Lighthouse CI fait échouer une pull request qui dégrade le score

Alléger le CSS

  • Le CSS bloque l'affichage : la page attend toutes les feuilles du <head>
  • CSS critique : les règles du haut de page en ligne dans le <head>, le reste chargé ensuite
  • Un seul fichier minifié et compressé, sans règles mortes. Pas de @import en cascade dans le CSS final

À retenir

  • HTML, puis CSS, puis JavaScript : <details>, <dialog> et la Popover API couvrent la plupart des composants, avec le clavier et l'accessibilité compris
  • Amélioration progressive : anchor positioning et View Transitions embellissent, @supports et un test de l'API assurent le repli
  • JS natif : délégation d'événements et état porté par les attributs ARIA, que le CSS réutilise
  • Web Components : réutilisables partout. Shadow DOM pour un widget isolé, Light DOM pour enrichir le HTML de votre framework
  • Performance : dimensions des images, police de repli ajustée, image LCP prioritaire. Mesurez avec Lighthouse
