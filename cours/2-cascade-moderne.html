Qui gagne ?

L'algorithme de la cascade

L'algorithme de la cascade

Quand plusieurs déclarations visent la même propriété du même élément, le navigateur compare ces critères dans l'ordre. Le premier qui les départage décide.

  1. Origine et importance : navigateur, utilisateur, auteur, puis les !important en sens inverse
  2. Contexte : Shadow DOM d'un Web Component
  3. Attribut style dans le HTML
  4. Couches (@layer)
  5. Spécificité du sélecteur
  6. Proximité de portée (@scope)
  7. Ordre d'apparition : la dernière déclaration gagne

La spécificité n'arrive qu'en 5e position. Les couches passent avant elle : c'est ce qui va nous permettre de ne plus jamais « gonfler » un sélecteur pour gagner.

L'héritage n'intervient qu'ensuite. Une valeur héritée du parent perd toujours contre une règle qui vise l'élément lui-même, même avec un sélecteur très faible.

Référence : la cascade sur MDN et la spécification Cascade 6.

Insister sur l'ordre : c'est la question n° 1 à se poser quand un style « ne s'applique pas ». Montrer l'onglet « Calculé » des DevTools qui indique la règle gagnante.

La spécificité, :is() et :where()

Sélecteur(id, classe, élément)
a(0, 0, 1)
.menu a(0, 1, 1)
.menu a[aria-current](0, 2, 1)
#nav .menu a:hover(1, 2, 1)
:is(#nav, .menu) a(1, 0, 1)
:where(#nav, .menu) a(0, 0, 1)

Les attributs et pseudo-classes comptent comme des classes, les pseudo-éléments comme des éléments.

  • On compare colonne par colonne, de gauche à droite : un seul id bat cent classes
  • :is() prend la spécificité de son argument le plus fort
  • :where() vaut toujours zéro : idéal pour des styles par défaut qu'on veut pouvoir surcharger
  • Les id servent aux ancres et aux formulaires, pas au style
Faire calculer à voix haute la 4e ligne. Les deux pseudo-classes sont Baseline depuis 2021.

La correction avec :where()

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #1b1e3c;
}

main {
  padding: 2rem;
}

.site-header {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
  align-items: center;
  justify-content: space-between;
  padding: 1rem 2rem;
  background: #1b1e3c;
}

.logo {
  margin: 0;
  font-weight: 800;
  color: #fff;
}

.menu ul {
  display: flex;
  gap: 1.5rem;
  margin: 0;
  padding: 0;
  list-style: none;
}

/* (0,0,1) : :where() compte pour zéro */
:where(.menu) a {
  color: #fff;
  text-decoration: none;
}

/* (0,1,1) : seul l'attribut compte, :where() vaut zéro */
:where(.menu) a[aria-current="page"] {
  text-decoration: underline;
  text-underline-offset: 0.3em;
}

/* (0,2,1) : :is() prend son argument le plus fort (.menu) */
:is(.menu, .site-footer) a:hover {
  text-decoration: underline;
}

/* (0,1,0) : gagne désormais contre :where(.menu) a */
.button {
  padding: 0.4em 1em;
  border-radius: 999px;
  font-weight: 700;
  color: #1b1e3c;
  background: #fff;
}
  • Les styles du menu tombent à (0,0,1) : n'importe quelle classe les surcharge
  • :is(.menu, .site-footer) factorise deux listes de sélecteurs
  • Rien n'a changé dans le HTML

Organiser ses styles

Couches, portées et imbrication

Les couches de cascade Baseline 2022

L'ordre des couches

@layer reset, base, components; déclare l'ordre une fois pour toutes. Entre deux couches, la dernière gagne, quelle que soit la spécificité.

Hors couche

Un style écrit hors de toute couche bat toutes les couches. Pratique pour un correctif rapide, dangereux comme habitude.

!important inversé

Pour les déclarations importantes, l'ordre s'inverse : la première couche gagne. Une règle d'accessibilité placée dans reset devient intouchable.
  • Une bibliothèque tierce s'importe dans sa couche : @import url("vendor.css") layer(vendor);
  • On retrouve l'architecture ITCSS (du plus générique au plus spécifique), garantie par le navigateur au lieu de la discipline de l'équipe
Documentation : https://developer.mozilla.org/fr/docs/Web/CSS/@layer. Ce sera l'ossature du framework du projet.

Une bibliothèque trop spécifique

/* Bibliothèque fictive « Slidy » : des sélecteurs très spécifiques */
.slidy .slidy__track {
  display: flex;
  gap: 1rem;
  overflow-x: auto;
}

/* Spécificité (0,3,1) : difficile à surcharger hors couche */
.slidy .slidy__track button.btn {
  border: 2px solid #999;
  border-radius: 0;
  color: #333;
  background: #ccc;
}
  • Un cas réel : un carrousel ou un sélecteur de dates arrive avec ses propres styles
  • Son bouton pèse (0,3,1). Hors couche, il faudrait un sélecteur encore plus lourd pour le restyler

Ranger chaque style dans sa couche

/* 1. L'ordre des couches, déclaré une seule fois en tête :
   en cas de conflit, la dernière couche gagne */
@layer reset, vendor, base, components, utilities;

/* 2. La bibliothèque tierce est rangée dans sa couche */
@import url("vendor.css") layer(vendor);

@layer reset {
  *,
  *::before,
  *::after {
    box-sizing: border-box;
  }

  body {
    margin: 0;
  }

  /* !important inversé : la PREMIÈRE couche l'emporte.
     Personne ne pourra réactiver les animations. */
  @media (prefers-reduced-motion: reduce) {
    *,
    *::before,
    *::after {
      transition-duration: 0.01ms !important;
      animation-duration: 0.01ms !important;
    }
  }
}

@layer base {
  body {
    font-family: system-ui, sans-serif;
    line-height: 1.5;
    color: #1b1e3c;
  }
}

@layer components {
  .container {
    max-width: 60rem;
    margin-inline: auto;
    padding: 2rem;
  }

  .card {
    flex: 0 0 16rem;
    padding: 1rem;
    border: 2px solid #d9dcea;
    border-radius: 1rem;
  }

  /* (0,1,0) mais couche « components » : gagne contre
     le (0,3,1) de la couche « vendor » */
  .btn {
    padding: 0.6em 1.2em;
    border: 0;
    border-radius: 999px;
    font: inherit;
    font-weight: 700;
    color: #1b1e3c;
    background: #2ec4b6;
    transition: background-color 0.2s;
  }

  .btn:hover {
    background: #ff7a59;
  }
}

@layer utilities {
  .card--sold-out {
    opacity: 0.6;
  }
}

/* Hors couche : bat toutes les couches (à réserver aux
   correctifs temporaires) */
.btn:disabled {
  cursor: not-allowed;
}
  • .btn (0,1,0) gagne contre la bibliothèque : sa couche est déclarée après vendor
  • La réduction des animations est en !important dans la première couche. Aucune couche suivante ne peut la défaire
  • .btn:disabled, hors couche, bat tout le reste

Les portées avec @scope Baseline 2026

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #1b1e3c;
}

.container {
  display: grid;
  gap: 2rem;
  max-width: 40rem;
  margin-inline: auto;
  padding: 2rem;
}

/* Portée en « donut » : de .card jusqu'à .card__content,
   sans entrer dans le contenu fourni par l'artiste */
@scope (.card) to (.card__content) {
  :scope {
    overflow: hidden;
    border: 2px solid #d9dcea;
    border-radius: 1rem;
  }

  /* Touche l'image de la carte, pas le portrait de la bio */
  img {
    display: block;
    width: 100%;
    height: auto;
    aspect-ratio: 16 / 9;
    object-fit: cover;
  }

  h2 {
    margin: 1rem 1rem 0;
  }
}

.card__content {
  padding: 0 1rem 1rem;
}

/* Proximité : le thème le plus proche du lien gagne,
   quel que soit l'ordre des règles */
@scope (.theme-light) {
  :scope {
    padding: 1rem;
    color: #1b1e3c;
    background: #fff;
  }

  a {
    color: #0b7a70;
  }
}

@scope (.theme-dark) {
  :scope {
    padding: 1rem;
    color: #fff;
    background: #1b1e3c;
  }

  a {
    color: #7fe3d8;
  }
}
  • @scope (.card) limite les règles aux descendants de .card, sans alourdir les sélecteurs
  • to (.card__content) fixe une limite basse : le contenu de l'artiste n'est pas touché (portée en « donut »)
  • À spécificité égale, la racine la plus proche gagne : les thèmes imbriqués fonctionnent
  • Disponible partout seulement depuis mars 2026 (Safari 26.4) : prévoir un repli pour les navigateurs anciens

L'imbrication native Baseline 2023

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #1b1e3c;
}

.container {
  display: grid;
  gap: 1.5rem;
  max-width: 48rem;
  margin-inline: auto;
  padding: 2rem;
}

.artist {
  display: grid;
  gap: 1rem;
  padding: 1rem;
  border: 2px solid #d9dcea;
  border-radius: 1rem;

  /* Sans & : un descendant (.artist img) */
  img {
    width: 100%;
    height: auto;
    border-radius: 0.5rem;
  }

  h2 {
    margin: 0;
  }

  /* & colle le sélecteur : .artist:hover, .artist:focus-within */
  &:hover,
  &:focus-within {
    border-color: #2ec4b6;
  }

  /* .artist.artist--headliner */
  &.artist--headliner {
    border-width: 4px;
  }

  /* & à la fin : .is-closed .artist */
  .is-closed & {
    opacity: 0.5;
  }

  /* Une media query imbriquée s'applique à .artist */
  @media (width >= 40rem) {
    grid-template-columns: 10rem 1fr;
    align-items: center;
  }
}
  • Le nesting du CSS natif, sans Sass
  • Sans &, la règle vise un descendant. Avec &, elle reprend le sélecteur parent : &:hover, &.artist--headliner
  • Une media query peut s'imbriquer dans la règle
  • Au-delà de trois niveaux, la spécificité grimpe et le code devient illisible

:has(), :user-invalid et :nth-child(… of S)

}

  grid-template-columns: auto 1fr;
  align-items: center;
}

input[type="email"] {
  padding: 0.5rem;
  border: 2px solid #5a5f80;
  border-radius: 0.5rem;
  font: inherit;
}

.field__error {
  display: none;
  margin: 0;
  color: #b42318;
}

/* :user-invalid attend que l'utilisateur ait modifié le
   champ : pas d'erreur rouge dès l'ouverture de la page */
input:user-invalid {
  border-color: #b42318;
}

/* :has() : le parent réagit à l'état d'un enfant */
.field:has(input:user-invalid) .field__error {
  display: block;
}

  justify-self: start;
  padding: 0.6em 1.2em;
  border: 0;
  border-radius: 999px;
  font: inherit;
  font-weight: 700;
  color: #1b1e3c;
  background: #2ec4b6;
}

.newsletter:has(:invalid) button {
  opacity: 0.7;
}

  • :user-invalid attend une saisie de l'utilisateur 2023
  • :nth-child(2n of .is-headliner) compte parmi les seules têtes d'affiche 2023
  • :not() accepte une liste de sélecteurs
  • :focus-visible : un contour au clavier, jamais un outline: none sans remplacement

Variables et couleurs

Custom properties, @property, oklch()

Pourquoi oklch() ?

oklch(L C H) décrit une couleur comme on la perçoit Baseline 2023 :

  • L : luminosité perçue, de 0 % à 100 %
  • C : chroma, l'intensité (0 pour un gris)
  • H : teinte, un angle (0deg rouge, 145deg vert, 265deg bleu)

Deux couleurs à la même luminosité ont vraiment le même contraste, ce que hsl() ne garantit pas : un jaune et un bleu « à 50 % » n'ont rien à voir.

  • color-mix() mélange deux couleurs dans un espace donné 2023
  • light-dark() donne une valeur pour le thème clair et une pour le sombre, selon color-scheme 2024
  • @property type une variable (<angle>, <color>…) : le navigateur sait alors l'animer 2024

Outil pour choisir : oklch.com.

Un thème piloté par des variables

/* Une teinte de marque, les autres couleurs en découlent */
:root {
  color-scheme: light dark;

  --brand-hue: 185deg;
  --color-brand: oklch(72% 0.13 var(--brand-hue));
  --color-accent: oklch(70% 0.17 35deg);

  /* light-dark() : 1re valeur en clair, 2de en sombre */
  --color-bg: light-dark(oklch(99% 0 0deg), oklch(22% 0.03 270deg));
  --color-text: light-dark(
    oklch(25% 0.05 270deg),
    oklch(95% 0.01 270deg)
  );

  /* 20 % de la marque mélangés au fond */
  --color-brand-soft: color-mix(
    in oklch,
    var(--color-brand) 20%,
    var(--color-bg)
  );
}

/* :has() sur la racine : réglages sans JavaScript */
:root:has(#dark-mode:checked) {
  color-scheme: dark;
}

:root:has(#hue-violet:checked) {
  --brand-hue: 300deg;
}

/* Variable typée : le navigateur sait l'animer */
@property --angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

@keyframes spin {
  to {
    --angle: 360deg;
  }
}

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: var(--color-text);
  background: var(--color-bg);
}

.container {
  display: grid;
  gap: 2rem;
  max-width: 28rem;
  margin-inline: auto;
  padding: 2rem;
}

.ticket {
  padding: 1.5rem;
  border: 6px solid transparent;
  border-radius: 1.5rem;
  background:
    linear-gradient(var(--color-brand-soft), var(--color-brand-soft))
      padding-box,
    conic-gradient(
        from var(--angle),
        var(--color-brand),
        var(--color-accent),
        var(--color-brand)
      )
      border-box;
  animation: spin 4s linear infinite;
}

.ticket__price {
  font-size: 2rem;
  font-weight: 800;
}

.ticket__cta {
  display: inline-block;
  padding: 0.6em 1.2em;
  border-radius: 999px;
  font-weight: 700;
  color: oklch(20% 0.03 270deg);
  text-decoration: none;
  background: var(--color-brand);
}

@media (prefers-reduced-motion: reduce) {
  .ticket {
    animation: none;
  }
}
  • Changer --brand-hue recalcule toute la palette : les variables sont résolues au moment du calcul, pas à l'écriture
  • :root:has(#dark-mode:checked) bascule le thème sans une ligne de JavaScript
  • Sans @property, --angle sauterait de 0 à 360deg sans transition
  • L'animation s'arrête si l'utilisateur a demandé moins de mouvement
Ouvrir la démo
Cocher les deux cases dans la démo. Montrer dans les DevTools la valeur calculée de --color-brand-soft.

À retenir

  • La cascade compare d'abord l'origine, puis les couches, puis seulement la spécificité
  • @layer range les styles du plus générique au plus spécifique. Plus besoin de gonfler un sélecteur
  • :where() pour les styles par défaut, @scope pour les composants
  • :has() et :user-invalid remplacent beaucoup de JavaScript
  • Une palette en oklch() et en variables se décline par calcul
  • Chaque nouveauté se vérifie sur Baseline avant de l'utiliser en production
Dans le projet, l'ossature de votre framework sera une série de couches, par exemple reset, tokens, base, layout, components et utilities.
